# DetRetLabel 测试素材包

已下载 COCO128 的 128 张真实图片、929 个真实目标框，涉及 71 种类别。
框由原始 YOLO 标签转换而来。JSON 中的置信度是固定种子生成的模拟数值，没有运行检测模型。
`05_` 中的错误为人工注入；这些数据用于功能测试，不能用于评估算法精度。

## 最快开始

1. 双击项目根目录的 `run.bat`。
2. 图片文件夹选择：`D:\Projects\DetRetLabel\test_data\coco128\images`。
3. JSON 选择：`D:\Projects\DetRetLabel\test_data\coco128\01_results_xyxy.json`。
4. 映射窗口确认：记录 `/results`、图片 `/path`、目标列表 `/detections`、框 `/bbox`、格式 xyxy、种类 `/type`、置信度 `/conf`。
5. 预期：128 张图片、929 个有效目标、0 条导入问题。
6. 可在算法或 GT 块中点击“导入 type-mapping…”，选择本目录的 `type-mapping.txt`。汽车、卡车、时钟等应显示为中文，其余未配置种类保留原值；点击“清除”恢复。
7. 标注几个目标后，在标注面板顶部点击“导出 Excel…”。核对三张表：进度包含全部 128 张已加载图片，目标明细同时保留原始种类与中文显示种类，未审核 / 待复核内容有明确状态。复核完成后可再次导出。

图片格式：{'.jpeg': 16, '.jpg': 96, '.png': 16}。PNG 由原图无缩放转换；JPEG/JPG 保留下载的原始字节。
JSON 路径故意混用 Linux / Windows 路径，均应按最后的文件名匹配。
原始压缩包中有 2 张图片缺少配套标签：images/000000000250.jpg, images/000000000508.png。
这些图片在 01/02/04/07 中作为显式空结果测试，在 ground_truth.json 中省略；不能据此认定图片没有真实目标。
逐图 `source_label_available` 字段和 manifest.json 对此作了明确记录。

## 可切换的 JSON

| 文件 | 测试用途 | 关键映射 |
| --- | --- | --- |
| `01_results_xyxy.json` | 推荐起点：每图一个目标列表 | `/results`, `/path`, `/detections`, `/bbox`, xyxy |
| `02_results_xywh.json` | 左上角 + 宽高数组 | `/results`, `/path`, `/detections`, `/xywh`, **xywh** |
| `03_results_flat.json` | 每条记录一个目标 | 根节点、`/name`、平铺记录、xmin/ymin/xmax/ymax、`/type`、`/score` |
| `04_custom_fields.json` | 嵌套自定义字段，测试手动链接 | 见下方说明 |
| `05_simulated_detection_errors.json` | 人工加入类别错误、漏框、额外框、低分正确框、空结果和缺少图片记录 | 与 01 相同 |
| `06_import_edge_cases.json` | 故意损坏部分目标、缺少置信度、无效图片字段、无效列表、未匹配文件名 | 与 01 相同，预期 5 条问题；缺少置信度的目标保留并排在末尾 |
| `07_filename_dictionary.json` | 直接以图片名作为字典键 | 根节点、字典键、`/detections`、`/bbox`、xyxy |
| `08_results_xywh_normalized.json` | 归一化左上角 xywh，按图片分组 | `/results`、`/path`、`/detections`、`/xywh`、**xywh，勾选归一化** |
| `09_results_flat_xywh_normalized.json` | 归一化左上角 xywh，每个目标一条 | 根节点、`/name`、记录本身、`/xywh`、**xywh，勾选归一化** |
| `10_results_xywh_fields_normalized.json` | 归一化 x/y/w/h 四独立字段，按图片分组 | `/results`、`/path`、`/detections`，坐标选 `/x`、`/y`、`/w`、`/h`，**xywh，勾选归一化** |
| `11_results_flat_xywh_fields_normalized.json` | 归一化 x/y/w/h 四独立字段，每个目标一条 | 根节点、`/name`、记录本身，坐标选 `/x`、`/y`、`/w`、`/h`，**xywh，勾选归一化** |
| `ground_truth.json` | 数据集真实框，不添加置信度 | 与 01 相同；置信度选择“不导入” |

`04_custom_fields.json` 手动映射：

- 记录位置：`/payload/frames`
- 图片：`/frame_meta/asset`
- 目标列表：`/hits`
- 坐标结构：四个独立字段；格式 xyxy
- xmin / ymin / xmax / ymax：`/geometry/left`、`/geometry/top`、`/geometry/right`、`/geometry/bottom`
- 种类：`/semantic/tag`
- 置信度：`/metrics/likelihood`

`08_` 和 `09_` 是由现有 `01_results_xyxy.json` 转换生成的附加素材，已逐图核对实际图片尺寸。共同映射为种类 `/type`、置信度 `/conf`；框字段 `/xywh` 表示 `[xmin/图片宽, ymin/图片高, 框宽/图片宽, 框高/图片高]`，不是 YOLO 中心点坐标。字段映射窗口中需要手动勾选“是否归一化坐标”。

两份均含 929 个目标，使用工具解析器回读验证为 0 条导入问题，还原为像素框的最大数值误差约 `1.14e-13` 像素。`08_` 保留全部 128 张图片记录，包括 2 张空目标图片；`09_` 每目标一个元素，仅 126 张有目标图片生成记录，另 2 张在图片列表中仍可加载。原有图片、目标顺序、种类和模拟置信度保留。

源素材有 39 个框伸出图片边界，转换未裁剪这些框，因此归一化坐标可能出现负数或右下边界超过 1。验证记录见 `reference/normalized_xywh_validation_report.json`。

当前源码通过独立的“导出有效目标json”按钮输出统一十字段平铺数组，归一化 x/y/w/h 及置信度为八位小数；`08_`、`09_` 的输入组织形式不影响输出规范。

`10_` / `11_` 分别由 `08_` / `09_` 直接拆分坐标数组生成，每个目标改为四个独立数值字段 `x`、`y`、`w`、`h`，仍使用归一化左上角 xywh。导入时将“坐标字段结构”选为“四个独立字段”，按顺序映射 `/x`、`/y`、`/w`、`/h`；种类 `/type`、置信度 `/conf`，并勾选归一化。两份各有 929 个目标、0 条导入问题，解析后的坐标、种类、置信度和原始目标顺序与对应数组版本完全一致。`10_` 保留 128 张图片记录，`11_` 的 126 张有目标图片生成 929 条记录。验证记录见 `reference/normalized_xywh_fields_validation_report.json`。二者均使用上述统一规范导出。

## 额外场景

- **格式筛选**：在主图片目录中取消 PNG 或 JPEG 勾选后，对应 JSON 记录应显示“图片未匹配”；重新勾选后恢复匹配。
- **重名冲突**：图片文件夹选择 `edge_cases/duplicate_names`，勾选包含子文件夹；JSON 选择 `edge_cases/duplicate_names.json`。预期两张同名图片、1 条“同名歧义”、0 个已关联目标。
- **图片损坏**：图片文件夹选择 `edge_cases/corrupt_image/images`，JSON 选择 `edge_cases/corrupt_image/results.json`。`broken.png` 被刻意损坏，选中时应显示解码失败，其余图片正常。
- **人工误检 / 漏检**：`reference/simulated_error_answer_key.json` 给出 05 中 6 个注入场景的图片、目标序号及遗漏框。
- **预期统计**：`reference/validation_report.json` 是用当前工具的解析器实际导入后得到的统计。
- **素材总览**：`preview_contact_sheet.jpg` 展示 16 张样例和数据集目标框；原始测试图没有绘制叠加框。
